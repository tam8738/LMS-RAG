# 06_FIGMA_DESIGN_MASTER_SPEC.md

Version: 1.0

> Master specification for Figma Make. Read AFTER Product Scope,
> Information Architecture and Screen Specification. This document
> defines HOW the product should look and behave.

------------------------------------------------------------------------

# 1. Design Objective

Build a modern AI SaaS product for university teachers.

The interface must communicate:

-   Professional
-   Calm
-   Premium
-   Trustworthy
-   AI-first
-   Document-first

Do NOT design:

-   LMS dashboard
-   Research paper portal
-   Social platform
-   Analytics dashboard

------------------------------------------------------------------------

# 2. Design Keywords

Minimal • Spacious • Elegant • Functional • Fast • Consistent

------------------------------------------------------------------------

# 3. Visual Hierarchy

Priority order:

1.  Primary Action
2.  Search
3.  Filters
4.  Document Content
5.  Metadata
6.  Secondary Actions

Every screen should have ONE clear primary action.

------------------------------------------------------------------------

# 4. Layout Rules

Header: - Sticky - Height 72px - Logo left - Navigation center - User
menu right

Content: - Max width 1440px - Comfortable margins - 8px spacing system

Footer: - Minimal - Utility links only

------------------------------------------------------------------------

# 5. Typography

Preferred fonts: - Inter - Be Vietnam Pro

Hierarchy

Display H1 H2 H3 Body Caption

Readable line length. Never use decorative fonts.

------------------------------------------------------------------------

# 6. Color System

Background: - Neutral

Surface: - White

Accent: - One primary brand color

Semantic: - Success - Warning - Error - Info

Borders remain subtle.

------------------------------------------------------------------------

# 7. Components

Document Card

Contains:

-   Title
-   Description
-   Subject
-   Tags
-   Author
-   Updated time
-   Publication Status

Hover:

-   Slight elevation
-   Softer shadow
-   Accent border

Search

Always placed above content.

Filters

Always near Search.

Primary Button

Filled accent.

Secondary Button

Outlined.

Danger Button

Only destructive actions.

------------------------------------------------------------------------

# 8. Motion

Allowed

-   Fade
-   Slide up
-   Hover elevation
-   Smooth transitions

Duration

150--250ms

Avoid excessive motion.

------------------------------------------------------------------------

# 9. Responsive

Desktop: Primary experience.

Tablet: Compact navigation.

Mobile:

-   Single column
-   Drawer navigation
-   Bottom sheet filters

------------------------------------------------------------------------

# 10. Empty States

Every screen needs:

-   Empty
-   Loading
-   Error

Include a clear next action.

------------------------------------------------------------------------

# 11. Screen Checklist

Login

-   Premium login
-   No marketing overload
-   Login card is dominant

Library

-   Search
-   Filters
-   Published documents only

Document Detail

-   Metadata
-   Download
-   AI Chat
-   Citations

My Documents

-   Dual status
-   Context actions

Upload

-   Simple flow
-   Clear validation

Admin Review

-   Queue
-   Detail
-   Approve
-   Reject
-   Archive

Profile

-   Name
-   Email
-   Role
-   Logout

------------------------------------------------------------------------

# 12. Design Do / Don't

DO

-   Keep whitespace generous
-   Keep typography strong
-   Prioritize usability
-   Keep components reusable

DON'T

-   Add trending/popular
-   Add social metrics
-   Add research-paper terminology
-   Invent new business features
-   Change business flow

------------------------------------------------------------------------

# 13. Final Validation

Before presenting any design, verify:

\[ \] Matches Product Scope \[ \] Matches Information Architecture \[ \]
Matches Screen Specification \[ \] Uses consistent components \[ \]
Responsive \[ \] Accessible \[ \] Premium AI SaaS feeling \[ \] No
out-of-scope features

If any item fails, revise before generating UI.
